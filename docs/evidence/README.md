# 项目记录与归档

JobGenie 仍处于持续开发和产品验证阶段。进展表中的“已完成”指具体功能、设计或文档里程碑，不表示整个产品完工、已经商业化或完成全部真机验收。

## 已有记录

| 记录 | 位置 | 能说明什么 | 边界 |
| --- | --- | --- | --- |
| 代码及修改记录 | Git / GitHub main | 功能变更、提交顺序、可复现版本 | Git 作者/提交时间可由提交者设置，不是独立工时或上传时间证明 |
| 里程碑与更新日志 | [项目进展表](../progress/README.md) | 交付范围、状态、证据关联 | 已标明历史补录，不是原始逐日工时表 |
| 验收说明 | docs 中各项 acceptance 文档 | 测试方法、结果和未覆盖边界 | 原始测试输出另行私存；引用历史结果不等于当天重测 |
| 设计记录 | [英文 iPhone 原型](../design/ios/README.md) | 页面范围、设计决策和版本说明 | 当前 Figma 链接可变化，尚未保存 .fig 或命名版本原件 |
| 线上版本 | GitHub Vercel check 与部署详情 | 某个提交的构建/部署状态 | 匿名页面可访问不等于所有生产业务都已验收 |

## 快照

执行 `node scripts/archive-project-evidence.mjs`，将快照保存到父工作区的私人 `records/jobgenie/snapshots/` 目录，包含：

- 当前提交 ID、提交日期元数据和工作区状态。
- Git bundle，以及该提交的已跟踪源码 tar。
- 当时的进展表副本。
- 尚存在的指定测试/构建原始日志。缺失的日志明确登记，不重新生成或伪装为历史原件。
- 文件大小、SHA-256、采集时间和来源清单；导出后验证哈希及 bundle。

快照对应 `capturedHead`，不包含未提交源码。文件哈希用于检查后续变动，不是第三方可信时间戳。归档完成后，可另存到自己控制的备份位置。

## 每次交付的记录

1. 在实际发生时记录需求、本人承担的工作、任务 ID 和产出。开始/结束时间由本人填写，不从 commit 数或工具运行时间推算。
2. 保存测试/构建输出，截图或录屏注明采集时间、对应版本、环境以及是否为演示数据。
3. 更新进展表并追加日志，提交和推送，核对 GitHub 远端 SHA。
4. 保存部署状态和版本链接；失败记录也保留，修复后新增记录。
5. 为重要设计里程碑手动导出 Figma 文件/截图或保存命名版本，记录与源码的对应关系。

执照、个人证件、学校往来、客户沟通、合同、账单、银行及支付原件留在私人目录，不提交到公开仓库。没有发生的客户、收入、开票、测试、工作时长和市场活动不补造。私人说明及模板应与原件分开，并标明整理日期。
