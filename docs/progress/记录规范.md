# 每次开发的留痕规范

生效日期：2026-11-04。范围：JobGenie 每次功能、修复或交付性工作。只使用当前目录原有的 `JobGenie项目进展.xlsx`。

## 目录

- `JobGenie项目进展.xlsx`：原进展表，任务编号保持稳定，更新日志只追加。
- `records/日期-JG-编号.md`：按任务关联下列四类记录；使用[模板](templates/开发交付记录.md)。
- `tests/日期/`：实际运行日志的公开脱敏版，包含成功及失败结果。
- `visuals/日期/`：已审阅截图、录屏或脱敏接口示例；注明真实、测试或演示环境。
- `deployments/`：平台状态查询结果，包含来源、查询时间、提交 SHA 和部署链接。
- `evidence-index.json`：历史文件来源、原件/归档件哈希及任务对应关系。
- `历史留痕索引.md`：历史里程碑入口；新增交付时同步延续索引或记录清晰入口。

## 必须逐项更新的四类记录

| 类别 | 每次记录 | 不适用或缺失时 |
| --- | --- | --- |
| 需求与关键决策 | 问题、范围、验收标准、实际需求调整及方案原因，关联任务和代码版本 | 简单修改写明一两句，不编造复杂讨论或未核实消息时间 |
| 测试与构建 | 实际命令、运行环境、开始/结束或输出中的时间、结果和日志路径 | 未运行写明原因；历史原始日志缺失就引用当时说明并标明缺失，不改写成新跑结果 |
| 成果画面或接口示例 | UI 变化保存实际截图/录屏；后端变化保存脱敏请求响应及预期结果 | 文档等无运行画面时写“不适用”；补拍写实际日期，不假装历史画面 |
| 部署 | 远端 SHA、平台检查结果、查询时间、部署 URL；区分网页、原生编译和应用分发 | 未部署、尚在构建、失败、没有检查分别记录，不把 Git push 等同于上线 |

## 交付顺序

1. 完成开发并按变更执行合适验证，保存真实输出。失败后修复并保留失败/重试的关联。
2. 审阅和脱敏日志、画面：个人路径、凭证、真实用户数据不得进入公开仓库。私人原件与公开版分开。
3. 更新四类记录、索引及原 Excel 的任务状态/追加日志。由本人填写的工时不自动推算。
4. 英文 commit，推送 GitHub，并核对远端 SHA。
5. 保存本次提交的部署查询结果。如果必须使用实现提交的固定链接，再提交一条记录更新，避免伪造自引用 SHA。
6. 最终说明实际完成、测试、推送及部署状态，保留尚未验收边界。

## 来源与真实性

历史回顾在 2026-11-04 整理，不倒填为原始记录。可核对的本轮 Git 克隆/开发起点为 2026-10-17；10 月 15/16 日仍为未证实的回忆线索。Git 日期和文件修改时间可变，文件哈希仅核对内容，不等于第三方可信时间戳。

现有验收文档保留在原路径，以固定提交链接引用，避免复制多套说明。进展表中的“已完成”仅指具体里程碑；产品仍在持续开发和验证，不能据此推断商业化、收入、实际工作小时或全部真机测试完成。
