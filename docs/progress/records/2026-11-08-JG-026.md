## Requirements and key decisions

The user requested the iOS product feedback feature on the web. Add the same two five-star questions, optional suggestions, Not now, permanent automatic suppression and voluntary entry. Share the existing campaign/response and account preferences with iOS, preventing duplicate answers across clients. Preserve legacy native requests that omit platform. Record web/iOS as declared analysis context.

Use the existing seven-day/three-UTC-date eligibility, two foreground minutes, 30-second idle period, maximum two offers and 14-day minimum deferral. Defer while editing, typing, dragging, selecting bulk items or saving. Do not select by outcomes or predicted sentiment. Neither score is preselected. Distinguish manual/prompt sources and reserved/shown offers. Nonresponse/experienced-user bias remains, and the recommendation question is not NPS.

Keep drafts only in memory. Persist account-scoped offline choices locally and retry idempotently after connection. Discard in-memory state and abort pending requests on account changes. A manual deferral also cancels unshown reservations across devices without creating a false display receipt. See [policy and acceptance](../../web-feedback-acceptance.md).
